# Issue #1 要件定義：ローカル動画生成環境の再現

## 目的・利用者

モデルの利用条件を満たす Mac 所有者が、自らライセンスに同意したうえで、導入・不足の診断・安全な再実行・直接生成・チャット生成・保存・再生を再現できる公開資料と実行用成果物を整備する。
本書は「何を・なぜ」を定める。配置・導入・検査の実現方法は設計書へ委ねる。確認済み事実は提供された検証結果に基づき、未実施の経路まで成功済みとは扱わない。

## 確認済み事実（2026-10-12）と前提

- Comfy Desktop 1.1.6 の既定インスタンスは `~/ComfyUI-Installs/ComfyUI/`、本体はその下の `ComfyUI/`。ComfyUI 0.39.2、Python 3.13.12、専用仮想環境、Manager V4 が有効。共有モデルは `~/ComfyUI-Shared/models/`、出力は `~/ComfyUI-Shared/output/`、API は `127.0.0.1:8188`。
- ノードは Registry に未公開（`minimax-h3-mlx` は見つからない）。固定コミットを `custom_nodes` に配置し専用仮想環境へ依存関係を導入した検証では、既存パッケージの更新・ダウングレードは発生しなかった。
- ノードはインスタンス側の models からモデルを解決した。検証では共有ディレクトリの実体をインスタンス側のシンボリックリンクから参照した。
- GUI 起動の ComfyUI の PATH に Homebrew が含まれず ffmpeg 解決に失敗した。検証ではワークフローの固定入力に ffmpeg の絶対パスを指定し、仮想環境の bin にリンクを置いて解消した。
- 直接スモーク生成は約52秒で成功。H.264（64×64、24fps、39フレーム）と AAC ステレオ32kHzを含み、エラー無しでデコードできた。秒数指定と実測フレーム数の一致は本書の合否条件にしない。
- 直接生成（768×448・5秒・steps=9・seed 42）は845秒で成功。1ステップ約60秒、途中から Qwen の応答と GPU を共用した区間は約100秒。H.264（768×448、24fps、124フレーム）と AAC ステレオを含み、エラー無しでデコードできた。
- 3モデルのディスク上の合計は約109 GiB（約117 GB）、Qwen は約18 GB、Desktop のインスタンスは数 GB。導入開始時の暫定下限150 GBは全工程の目安であり、容量保証や取得スクリプトの固定下限ではない。
- Harness は当該プラグインの peer 依存が0.1.xのみのため導入を拒否した。上流 Issue と未マージ修正 PR があり、利用者の明示承諾後に公式の完全一致バージョン例外で導入した。上流報告ではこの組合せのバックグラウンド実行（async）が失敗しうる。
- Harness が参照するキーは `~/.dsh/.env` のダミー値で解決し応答した。Harness は実行中に desktop profile の `cordis.patch.yml` を書き換えるため、設定例の適用時は既存項目を保持すること。
- Ollama は `127.0.0.1:11434` で待受し、Qwen はツール呼び出しに対応。262144はこの機体の搭載メモリから Ollama が決めた既定コンテキスト長であり、他機体の既定値や推奨値ではない。
- Harness Desktop の再起動後にプラグインが読み込まれ、`qwen3.8:27b-mlx` のチャットから登録済みワークフロー一覧と対象ノードを取得できた。
- チャット生成（同期実行・スモーク条件・プロンプト指定）は61秒で成功。ComfyUI 履歴の実投入グラフは登録ワークフローとノード構成・固定入力が一致し、差分は公開6項目だけ（シードはランダム化）。H.264（64×64、39フレーム）と AAC ステレオを含み、エラー無しでデコードできた。同時刻の Ollama サーバーログに `/v1/chat/completions` の要求記録がある。
- チャット生成の前後のシステム全体のメモリ空き率は40〜60%、Qwen は約21GBを使用。Ollama のコンテキスト長は既定の262144、Harness のモデル定義は contextWindow 65536のままだった。
- 待受は ComfyUI `127.0.0.1:8188`、Ollama `127.0.0.1:11434`、Harness Desktop は起動中に `127.0.0.1` の動的ポートであり、いずれもループバックのみ。この構成のバックグラウンド実行（async）は未検証。
- `comfyui_run` は任意の API 形式ワークフローを投入できる（パッケージ型定義で確認）。プラグインだけで LLM の変更可能入力を技術的に限定できるという前提は置かない。

## 非スコープ

- モデル重みのリポジトリ収録、image-to-video、クラウド実行、初回 GUI ウィザードの自動化、対象構成以外の動作保証、速度・画質の最適化。
- 版ずれ検出の自動化：今回は指定構成と検証記録で追跡し、追加の自動検出は行わない。
- 成功再現率の規定：反復回数・確率保証より、各経路の実機成功と検証条件の記録を優先する。
- 副作用範囲の網羅：全アプリの変更範囲の網羅は対象外。権限・シェル設定・既存データの保護は下記に定める。
- CI 整備・CI での動画生成：今回はローカル・対象機の検証を優先し、Actions のコストを抑える。
- 設定キー名の移設：指定 Harness 版の既存契約を維持し、設定構造の変更は行わない。
- リポジトリ自体のライセンス選定・アンインストール手順：今回は導入・生成再現に限定し別途検討する。
- Harness 側のツール承認・無効化：任意投入を制限できるかの調査は別途とし、今回は利用者判断のリスク案内に留める。
- 公開6項目の値の上限：上限は設けず、検証済みの生成条件と、大きな値がメモリ消費・所要時間に与える影響を案内する。

## 機能要件

- **FR-1 導入案内**：対象構成、各モデル容量と実測合計、暫定下限・追加消費、配置構造、自動化境界、導入順序、初回 GUI 起動を README で説明する。README の容量案内は日付・取得範囲付きの実測記録を参照する。
- **FR-2 ライセンス確認**：取得対象ごとの原文参照・確認日・非正本の要約を示す。H3 の米国・EU・英国・韓国の利用対象外、年商2,000万USD超の別途許諾を案内し、派生2モデルにも H3 の条件が及ぶ前提で、3モデルの取得前に利用者自身の同意を求める。未同意ではどのモデルも取得しない。
- **FR-3 取得・導入**：自動化境界表の対象を取得・配置でき、開始前に対象・リビジョン・必須ファイル一覧・配置先・空き容量を確認する。取得と D-3 は共通の存在・バイトサイズ基準を用いる。容量下限はこれから取得する残量に応じてスクリプトの配置先ボリュームで判定し、Qwen 分を含めない。不足時は取得を開始せず原因表示・非ゼロ終了とし、全対象が完了済みなら再取得せず成功終了する。
- **FR-4 チャット環境**：利用者が手順書に従って設定例を既存項目を保持して追記し、Harness の既定モデルをローカル Ollama の Qwen に切り替える。応答と提供元の証跡として、応答時刻と対応づけられる Ollama サーバーログの要求記録を得る（稼働モデル表示だけでは不可）。プラグイン導入・接続を確認し、互換性例外のリスクと必要な明示承諾を先に案内し、利用者が手で例外導入する。async の既知の制約と、検証した実行方式を記録する。
- **FR-5 診断**：下記 D-1〜D-9 をすべて確認し、各項目の状態を表示する。全項目が正常なら成功、不足・不正・確認不能があれば該当項目と原因を表示して非ゼロ終了する。
- **FR-6 直接生成**：API 形式ワークフローで生成完了・保存先・動画の存在を確認し、H.264 映像と AAC 音声の両ストリーム、要求解像度との一致、エラー無しの全フレームデコードを再生成功の合否基準とする。投入スクリプトは実行エラー・拒否・タイムアウトを原因表示・非ゼロ終了で伝える。スモーク条件は64×64・1秒・steps=5（出典：固定ノードの README）とする。
- **FR-7 チャット生成**：標準経路はプラグインのライブラリに登録した FR-6 のワークフローを、公開パラメータ（プロンプト・幅・高さ・秒数・ステップ・シード）だけで実行する。モデルパス・`ffmpeg_path`・保存先は公開パラメータにしない。「同じワークフロー」はノード構成と固定入力が一致し公開パラメータだけが異なること。生成・保存先・動画の存在と FR-6 の再生合否まで確認する。
- **FR-8 検証記録**：成果物と FR・AC・要件・Issue 設計・マスター設計書の対応、実行条件・手順・結果・証跡・失敗時の対処を記録する。公開する検証記録はテキストとし、所在はリポジトリ内の文書（設計で場所を定める）とする。手順ごとに「クリーン状態で検証／既存環境で検証／未検証」を記す。クリーン状態は当該手順の導入対象と取得途中データが存在しない状態とし、開始時状態を記録する。ノード・プラグインの事前確認は観点・対象版／リビジョン・日付・未確認範囲を記し、安全性の全面保証とは扱わない。

## 非機能要件（安全性・再現性・冪等性・メモリ）

- **信頼境界**：ComfyUI・Ollama・Harness は信頼できるローカル利用者向けとし、待受をループバックに限定して診断する。認証不要の API を外部公開しない。
- **残余リスク**：`MiniMaxH3SaveVideo` の `ffmpeg_path` は任意の実行ファイルパスを受け取る。公開パラメータ制限は標準経路の約束であり、エージェントの `comfyui_run` による任意投入を遮断するものではない。外部サイトの文章・第三者のファイルなど信頼できない入力を、そのままエージェントに実行させない運用上の注意を README に明記する。Harness 側のツール承認・無効化は未調査であり、任意投入の許可は利用者判断のリスクとして README に示す。
- **公開物の安全性**：モデル重み・秘密情報・個人を特定する絶対パスを公開成果物・テキストの検証記録に含めない。PR・Issue に貼る記録も同じ点検の対象にする。ホームを `~` に統一するのは文書だけとし、実行物のパスは実行時に解決する。設定例の認証値は秘密ではないダミー値に限る。
- **権限・設定**：スクリプトは管理者権限を要求せず、シェル設定・Harness の profile を書き換えない。設定例の適用・再適用とプラグインの互換性例外は手順書のみとし、利用者が手で行う。README は設定例を既存項目を保持して追記する注意を示す。
- **再現性**：指定版・リビジョン、ノード構成・固定入力・公開パラメータと生成結果を追跡可能にし、導入から両経路の生成・保存・再生までを再現対象とする。動画のバイト単位の一致は要求しない。
- **冪等性**：同条件の2回目は全対象を完了済みと判定して成功終了し、完了済みファイルを再取得せず、既存ファイルを変更・削除しない。サイズ不一致を含む不一致・来歴不明・取得途中の対象データは変更せず、状態と対処を表示して非ゼロ終了する。これらを変更する動作は提供せず、利用者が自分で該当ファイルを退避してから再実行する。一覧外の余分なファイルはこの拒否対象にせず許容する。
- **メモリ**：この機体の既定コンテキスト長262144、INT8 Transformer 約38GB、テキストエンコーダ約67GBのストリーミング読み込みを踏まえ、コンテキスト抑制・モデル解放・同時実行削減と逼迫時の症状・対処を案内する。128GBでの無条件の併用を保証せず、推奨値と実測条件を区別する。

## 制約

- Hugging Face の対象3リポジトリはゲートなしで未ログイン取得可能だが、利用条件の確認・同意は省略しない。
- Harness は Ollama にもキーを要求し、未設定では `No API key for provider` になる。設定例は desktop profile の `cordis.patch.yml` の `llm-pi-ai.providers`、`api: openai-completions`、`agent-default-model`、`apiKeyEnv` に対応すること。
- プラグインの互換性拒否を黙って回避しない。手順書は拒否メッセージ・例外のリスク・承諾が必要であることを先に示す。利用者が手で行う公式の `dsh plugin allow-version ... --accept-risk` による完全一致バージョン例外の対象・拒否の出力・承諾の事実を検証記録に残す。
- ローカル検証を優先し、直接・チャットの生成・保存・再生確認は対象機で行う。検証記録があることと本書の全 AC 達成は区別する。

## 受け入れ条件

AC-1〜AC-9 は Issue の9項目と同じ順序、AC-10〜AC-12 は補足条件。番号は維持する。
