# Issue #1 要件定義：ローカル動画生成環境の再現

## 目的

利用者がモデルライセンスへの同意と利用条件の確認を自ら行ったうえで、Mac への環境導入からチャット指示による動画生成・保存・再生までを再現できる資料と実行用成果物を整備する。

## 背景

Mac 上で MiniMax H3 と ComfyUI を組み合わせる環境が手作業で構築済み／構築中であり、その知識を public リポジトリ `shuhei-suzuki/ai-video-generator` に残す必要がある。
本書の確認済み事実は、Issue 本文と依頼時に提供された検証結果に基づく。環境全体の生成成功を本書作成時点で検証済みとは扱わない。

## 利用者と利用シーン

- 対象の Mac を所有し、モデルの利用条件を満たす利用者が、初めて環境を導入する。
- 利用者が導入済み環境の不足を診断し、取得・導入を安全に再実行する。
- 利用者がテキストから動画を生成し、Harness のチャット経由でも同じワークフローの結果を保存・再生する。

## スコープ

- macOS 26、Apple Silicon（基準機：M5 Max）、メモリ 128GB のローカル環境。
- 次の対象構成について、バージョン・固定リビジョン・配置先を利用者が確認できること。

## 非スコープ

- モデル重みのリポジトリへの収録、image-to-video、クラウド実行、CI での動画生成。
- Comfy Desktop と DeepSeek Harness の初回 GUI ウィザードの自動化。
- 対象構成以外の動作保証、生成速度・画質の最適化。

## 機能要件

- **FR-1 導入案内**：対象構成、容量、配置構造、導入順序、人手が必要な初回起動を説明する。
- **FR-2 ライセンス確認**：MiniMax H3 Community License の参照先、米国・EU・英国・韓国の利用対象外、年商2,000万USD超の別途許諾などの制限を示し、モデル取得前に利用者自身の同意を求める。同意がなければ取得を開始しない。
- **FR-3 取得・導入**：指定リビジョンのノードと必要なモデルを取得・導入でき、実行前に取得対象・リビジョン・配置先を確認できる。
- **FR-4 チャット環境**：設定例で Harness の既定モデルを Ollama に切り替え、応答を得られる。`dsh-comfyui` 0.5.4 の導入と ComfyUI への接続を確認できる。
- **FR-5 診断**：必要なサービス、4 ノード、モデル配置、ffmpeg を確認し、不足時は原因を示して失敗する。
- **FR-6 直接生成**：API 形式ワークフローを投入し、生成完了・保存先を確認して、保存された動画をローカルで再生できる。
- **FR-7 チャット生成**：Harness のチャット指示から FR-6 と同じワークフローを投入し、動画の保存先まで確認できる。
- **FR-8 検証記録**：成果物と要件・設計・マスター設計書の対応を示し、実行条件・手順・結果、検証済み／未検証の区別、代表的な失敗と対処を記録する。

## 非機能要件（安全性・再現性・冪等性・メモリ）

- **安全性**：ComfyUI API と認証不要の Ollama API はローカル利用に限定し、外部公開しない。ComfyUI は既定の `127.0.0.1` 限定を前提とする。
- **安全性**：固定ノードの事前確認結果では外部通信などは確認されていないが、`MiniMaxH3SaveVideo` の `ffmpeg_path` は任意の実行ファイルパスを受け取る。信頼できるローカル利用者・ワークフローのみを対象とし、この入力の危険性と外部公開禁止を明記する。
- **安全性**：モデル重み・秘密情報・個人の絶対パスを公開成果物に含めず、ホームは `~` と表記する。設定例の認証値は秘密ではないダミー値に限定する。
- **再現性**：指定バージョン・リビジョンと検証時の入力・生成条件・結果を追跡可能にする。再現対象は導入と生成・保存までの手順であり、動画のバイト単位の一致を要求しない。
- **冪等性**：取得・導入の再実行で、既存データを不用意に上書き・削除しない。不一致・取得途中・失敗時の状態を利用者が判別でき、対処を案内できる。
- **メモリ**：Ollama の既定コンテキスト長 262144、INT8 Transformer 約38GB、テキストエンコーダ約67GBのストリーミング読み込みを考慮した併用指針を提供する。
- **メモリ**：コンテキスト長の抑制、不要なモデルの解放、実行の同時性を減らす判断を案内し、メモリ逼迫時の症状・対処と検証条件を記録する。128GB でも無条件に同時実行できるとは扱わない。

## 制約

- 導入開始時の空きディスクは 150GB 以上を必要とする（動画用モデル約117GB＋Qwen 約18GB）。生成物・キャッシュ等による追加消費にも注意を促す。
- Hugging Face の対象3リポジトリはゲートなしで未ログイン取得可能だが、利用条件の確認・同意は省略できない。
- Harness は認証不要の Ollama に対してもキーの存在を要求し、未設定では `No API key for provider` で失敗する。ダミー値で動作することは提供情報で確認済みである。
- Harness 設定例は Desktop profile の `cordis.patch.yml` における `llm-pi-ai.providers`、`api: openai-completions`、`agent-default-model`、環境変数参照 `apiKeyEnv` に対応すること。
- ローカル検証を優先して GitHub Actions の実行コストを最小化する。生成・保存・再生とチャット連携の確認は実機で行う。

## 受け入れ条件

AC-1〜AC-9 は Issue の受け入れ条件9項目と同じ順序で対応する。AC-10〜AC-12 は追加事実に基づく補足条件である。

- **AC-1**：README に対象構成と固定リビジョン、各モデル容量、空き容量150GB以上、配置構造、導入順序が記載されている（FR-1）。
- **AC-2**：README で公式ライセンス参照先と FR-2 の制限を確認でき、取得前に同意を求める。未同意での実行ではモデル取得が開始されない（FR-2）。
- **AC-3**：取得・導入スクリプトが指定リビジョンを使い、対象・配置先を確認できる。同条件で2回実行しても既存データが不用意に変更・削除されず、不一致・取得途中の状態も識別できる（FR-3、冪等性）。
- **AC-4**：設定例で Harness から Ollama の既定モデルの応答を取得でき、`dsh-comfyui` 0.5.4 の導入・接続確認を手順どおり再現した結果がある（FR-4）。
- **AC-5**：正常環境でヘルスチェックが成功し、サービス・各ノード・モデル配置・ffmpeg の不足をそれぞれ与えた場合、該当原因を表示して失敗する（FR-5）。
- **AC-6**：投入スクリプトで API 形式ワークフローを実行し、生成完了、保存動画の存在、ローカル再生の成功を実機で確認した記録がある（FR-6）。
- **AC-7**：Harness のチャットから AC-6 と同じワークフローを投入し、生成成功と動画保存先を確認した指示・手順・結果が記録されている（FR-7）。
- **AC-8**：要件・設計・マスター設計書が成果物に対応し、検証済み／未検証と、サービス未起動・モデル不足・キー未設定・メモリ逼迫など代表的失敗の対処が明記されている（FR-8）。
- **AC-9**：公開対象ファイルの確認でモデル重み・秘密情報・個人の絶対パスがなく、ホームの表記が `~` に統一されている（安全性）。
- **AC-10**：外部公開禁止と `ffmpeg_path` の危険性が明記され、実機検証時に ComfyUI・Ollama の待受がループバックに限定されていることを確認した記録がある（安全性）。
- **AC-11**：推奨スモークテストの64×64・1秒・steps=5で保存・再生を確認し、生成条件と結果を記録している（FR-6、再現性）。
- **AC-12**：メモリ併用指針と逼迫時の対処があり、128GBの対象機でチャット生成を確認した際の Ollama コンテキスト長、モデル稼働状態、メモリ状況が記録されている（メモリ）。

## 未確定事項

- 対象機で安定して併用できるコンテキスト長・生成条件・同時実行範囲と、実測のメモリ使用量・生成時間。
- ノード・動画の具体的な配置先、ffmpeg の検証対象バージョン、生成物・キャッシュ込みの追加空き容量。設計と実機検証で確定し、利用者向け資料に反映する。
- 直接投入・チャット投入による生成から再生までの実機検証結果。未確認の成功を記録せず、AC-6・AC-7・AC-11・AC-12 の確認をもって確定する。
